# Codex Workspace Blueprint

一套可复用的 Codex 工作空间编排参考，重点解决两个问题：长期任务中上下文携带过多，以及外部记忆自动注入造成的噪声。

这个仓库只包含通用架构、规则示例和项目状态模板，不包含任何实际项目、业务资料、自定义 Skill、凭据、个人路径或本机 Codex 配置。

## 核心设计

- `AGENTS.md` 只保留常驻、跨任务都有效的最小规则。
- 详细流程按任务类型放在文档中，需要时才读取。
- 长任务用一个 `PROJECT.md` 作为唯一状态真源，避免多个上下文文件互相冲突。
- 每个任务只维护一个“活跃工作集”：目标、边界、决定、门禁、证据与下一动作。
- 外部记忆只按需查询，不自动召回或采集；当前工作区事实始终优先。
- 搜索、日志和工具输出先筛选、统计、落盘，再把最少必要证据带入上下文。

## 使用方式

1. 阅读并按自己的偏好修改根目录 `AGENTS.md`。
2. 把 `docs/` 中真正适用的原则整合进自己的工作空间；不要整套无差别加载。
3. 只有长任务、跨窗口任务或阶段性交付才创建 `PROJECT.md`，可从模板复制。
4. 如果使用 Memmy 或其他记忆系统，将其改成“明确请求时才检索”，并限制返回数量和正文长度。
5. 用根目录、项目子目录、同仓库 worktree 和相似路径分别验证规则是否生效。

Codex 会在开始工作前读取适用范围内的 `AGENTS.md`。具体层级和覆盖方式以 [OpenAI 官方 AGENTS.md 指南](https://developers.openai.com/codex/guides/agents-md) 为准。

## 不要直接公开的内容

- `.codex/config.toml`、Hooks、数据库、缓存和备份。
- `.env`、令牌、密钥、账号信息和真实服务地址。
- 本机绝对路径、用户名、设备名和私人目录结构。
- 项目正文、客户资料、内部决策、日志、输入输出和生成产物。
- 自定义 Skill 的实现、清单、安装路径和插件连接配置。

仓库中的字符数量不等于模型实际计费 Token。优化效果应以真实任务中的上下文内容、召回结果和使用量观测为准。

## 边界

这是一套个人实践提炼出的模板，不是 OpenAI 官方配置，也不包含 Memmy 本身的代码或配置。请根据自己的隐私要求、工具链和任务规模调整。
