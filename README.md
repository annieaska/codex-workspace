# Codex 个人业务工作区参考

这是一个可供参考的个人业务工作区蓝图，用于展示如何组织业务运行、项目、知识、能力模板、人工确认记录和系统说明。使用者可以按自身需求选用，不必照搬全部目录和规则。

在采用这套结构的工作区内，仓库是业务资料真源，各项目的 `PROJECT.md` 是项目状态与决策的权威入口；外部记忆或运行工具只提供辅助线索。

## 使用入口

- 临时输入进入 `00_工作台/01_收件箱`。
- 业务材料按用途进入 `01_业务运行`。
- 有明确目标和交付物的工作进入 `02_项目`。
- 可复用知识、方法和模板分别沉淀到 `03_知识库` 与 `04_能力库`。
- 软件产品的测试与发布前验证遵循 `04_能力库/02_SOP/软件产品QA工作流.md`。
- 只有人工确认后的事实、偏好、决策和经验进入 `05_确认记录`。
- 环境与工具说明进入 `06_系统说明`，不得保存任何密钥。

## 默认开发与验证节奏

软件和 Web 修改默认按以下顺序推进：

1. 先收敛会影响实现路线的需求、边界和验收标准。
2. 在已确认范围内集中完成实现，不边开发边运行常规测试；此时形成的是可验证候选，不代表已经验收、提交或发布。
3. 实现完成后，只做与本次变更匹配的最小充分定向验证。

默认不运行全量测试，不做整站探索，也不为增加用例数量而新增测试。定向验证失败时，只修复已发现的问题，并复验失败项及受修复影响的检查；没有新变化、失败或明确风险时即停止。只有用户明确要求，或存在安全、数据损坏、广泛回归等具体证据时，才提高验证强度。

Git 提交、推送、合并和发布均不自动执行，必须由用户明确授权。

## 参数准确性与审核门禁

交接、派发和审核使用单一参数真源，并记录可定位的路径或标识及版本、提交号或内容哈希。未变化的参数和配置只完整提供一次，后续只引用真源并传递增量。存在多个参数真源、新旧参数并存、引用无法定位或校验不一致时，审核不通过；复现所需的最小重复内容应说明用途。项目可在 `PROJECT.md` 中使用 `04_能力库/04_模板/PROJECT.template.md` 提供的字段和完成标准记录该门禁。

## Codex 规则说明

- 仓库根目录的 `AGENTS.md` 是这套参考工作区的推荐规则，随仓库版本管理，作用于本仓库及其下级目录。
- 本仓库不存储、不备份、也不同步任何人的 `~/.codex` 用户级配置；个人设置由使用者在自己的本地环境中独立管理。
- 参考者可以复制或改写所需规则，但应根据自己的项目范围、风险和交付方式调整，而不是直接把示例当作通用强制配置。
