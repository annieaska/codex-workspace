# Matt 本地过程文件规则

## 使用范围

- 仅三级“Matt 复杂执行”按实际需要创建过程文件。
- 一级和二级任务不得为了套用流程而预建地图、规格或工单。
- 本工作区不使用 GitHub Issues、外部工单系统或仓库根目录 `.scratch` 管理 Matt 状态。

## 存放位置

Matt 过程文件统一放在当前项目内部：

```text
<项目>/02_工作区/Matt执行/
├── map.md       # 仅使用 Wayfinder 时创建
├── architecture.md # 仅三级需要新架构设计时创建
├── adr/          # 仅存在重要且难以逆转的架构决定时创建
├── spec.md      # 仅需要固化规格时创建
└── issues/      # 仅需要依赖工单时创建
```

- 不预先创建空目录或占位文件。
- `architecture.md` 只保存已确认的架构方案及其需求摘要、边界、数据流、失败模式和取舍；草案在确认前不得被后续 Matt 阶段视为事实。
- ADR 只记录同时满足“难以逆转、存在真实取舍、脱离上下文会令人困惑”的重要决定，不为普通实现选择批量建档。
- 工单格式沿用当前 Matt Skill 的规范，不在工作区另建一套标签和状态机。
- 原型、验证记录或实现材料仍按项目需要放在 `02_工作区`；最终成品放在 `03_交付物`。

## 状态同步

- `PROJECT.md` 是唯一项目状态真源；`map.md`、`architecture.md`、`adr/`、`spec.md` 和 `issues/` 只是执行过程制品。
- 每次阶段门禁只把关键结论、当前级别、完成情况和下一动作摘要写回 `PROJECT.md`，不复制整份架构或过程文档。
- 已有任务接入 Matt 时继承现有决策、原型和验证证据，只对未完成工作建图或拆票，不重新开始需求发现。
- 过程文件与 `PROJECT.md` 冲突时，以已确认的 `PROJECT.md` 为准并先校正过程文件。

## 结束条件

- 剩余工作不再需要依赖图或跨窗口连续性时，允许自动降级并停止新增 Matt 文件。
- 项目收口时把最终状态与交付物链接写回 `PROJECT.md`；Matt 过程文件留作项目内证据，不迁移到工作区根目录。
