# 上下文与外部记忆

## 活跃工作集

每个任务只维护一个活跃工作集，内容包括：

- 当前目标、验收条件和明确不做项。
- 已授权范围、约束、已确认决定和未关闭整改。
- 当前步骤、门禁、必要路径或版本、活跃错误。
- 最新有效验证、风险和下一动作。

已经解决的历史、完整日志、旧产物和未使用参考资料只保留可回查路径，不持续塞进会话。

整改遵循根目录 `AGENTS.md` 的“Corrections and closure evidence”：在既有锚点中简记“要求｜状态与缺口｜关闭证据”，必要时补充“什么不能算通过”。保留原始范围与验收，替换过期完成结论；已关闭项只留结论和证据链接，过程归入既有历史章节。短任务不新增状态文件。

## 读取策略

- 搜索先限定对象、目录、时间范围和结果数量。
- 长文档首次只读相关章节，后续只读变化段。
- 大输出在执行端筛选、统计或落盘，只返回支持当前判断的关键证据。
- 文件、规则、环境和输入未变化时，复用仍可追溯的验证结果。
- 图片和批处理任务按批固定输入与验收，只返工失败项。

## 读取分流与证据回查

- 默认路径是“具体问题 → 限定文件/章节 → 检索与执行端过滤 → 关键证据 → 主模型判断”。小文件、已知函数和局部修改直接读取；不机械套用 350 行等硬阈值，不安装拦截读取的钩子。
- 多份大资料仅在定向检索仍不足时考虑摘要或索引；复用现有可用工具，避免先把全文送进主模型再摘要。摘要返回问题对应结论、来源路径与章节/符号、必要短摘录、未覆盖范围及不确定项；行号必须来自原文检索，不由摘要模型猜测。
- 摘要只作定位线索。修改前读取目标段及必要上下文；调试根因、架构取舍、权限/资金/安全逻辑和最终验收由主模型依据原始证据判断。“未检索到”不等于“不存在”，摘要不能代替测试退出码或完整的相关失败证据。
- 小模型读取属于可选能力，当前不自动启用。仅在已有明确委派授权、模型与数据边界可用、任务可独立且预期收益大于协调成本时使用；限定问题、输入和输出，避免复制整段会话。辅助模型只读提取，主模型保留修改与验收责任；不因本规则新增外部服务、凭据或模型切换。
- 检索/摘要漏项、来源不明、超时或发生冲突时，停止该次分流，定向回查原文；不要反复委派。工具不可用时使用现有本地检索，不阻断正常业务开发。
- 衡量整项任务的主模型与辅助模型用量、缓存、耗时及返工；只利用已有可追溯数据，不新增监控。输出字符减少不等于 Token 或账户额度同比减少；没有同口径数据就标注未测量，不承诺固定节省比例。

参考：[Spotify shunt 原文](https://engineering.atspotify.com/2026/9/portal-by-spotify-cut-my-claude-code-token-usage-by-90)、[Codex 子 agent 配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)。本工作区采用读取与回查原则，未接入 Portal/shunt 服务。


Spotify 的“90%”来自特定读取场景的主模型 Token 对比，不代表整个 Codex 账户额度节省；辅助模型仍有用量，额外调用也可能增加等待和漏项返工。这里仅采用规则，不安装 shunt 或启用外部模型。

## 压缩与恢复锚点

长任务在压缩、跨窗口或阶段变化前更新一个增量锚点，至少保留：目标、验收、不做项、授权、决定、精确标识、活跃错误、最新验证、风险和下一动作。恢复时先读取锚点，再按需追溯证据，不重读全部资料。

锚点同时保留未关闭整改。恢复或交接时核验目标、完成结论、未关闭要求、门禁和第一动作是否一致；矛盾时定向回查原始要求与对应版本的关闭证据。已确认的决定直接继承，只在缺少实质业务决定时澄清，不新增常规批准或全量复验。

## Memmy 或其他记忆系统

外部记忆应作为历史线索，而不是当前事实来源。推荐原则：

- 对指定工作空间关闭自动召回、自动采集和自动提交，但保留既有历史。
- 只有用户明确要求回忆，或完成当前任务确实缺少历史事实时才查询。
- 限制返回条数和正文总量，并携带来源以便核对。
- 过滤过期、重复、无关和敏感内容。
- 当前用户指令、项目状态与工作区文件始终优先于记忆。
- 记忆服务不可用时，当前任务仍应继续，不把它当成硬依赖。

公开仓库中不要提交真实 Hook、数据库、缓存、备份、本机路径、账号配置或服务地址。这个仓库也不提供任何第三方记忆工具的代码。

## 最小验证矩阵

以下是适用场景清单。只检查本次变化影响的行为，复用有效证据；文档措辞调整不自动重跑 Hook、跨目录或业务测试。涉及实际记忆配置变更时，按影响范围选择：

| 场景 | 预期行为 |
| --- | --- |
| 工作空间根目录 | 常驻规则生效，不自动注入历史记忆 |
| 项目子目录 | 继承工作空间规则，并读取项目自己的状态真源 |
| 同仓库 worktree | 行为与主工作区一致 |
| 名称相似但不属于该工作区的路径 | 不被错误排除或套用规则 |
| 用户明确要求回忆 | 仅返回少量相关片段并提供来源 |
| 记忆服务不可用 | 任务继续，说明缺少的历史证据 |
| 插件或应用更新后 | 重新确认 Hook 入口与作用范围 |
