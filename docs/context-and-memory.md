# 上下文与外部记忆

## 活跃工作集

每个任务只维护一个活跃工作集，内容包括：

- 当前目标、验收条件和明确不做项。
- 已授权范围、约束和已确认决定。
- 当前步骤、门禁、必要路径或版本、活跃错误。
- 最新有效验证、风险和下一动作。

已经解决的历史、完整日志、旧产物和未使用参考资料只保留可回查路径，不持续塞进会话。

## 读取策略

- 搜索先限定对象、目录、时间范围和结果数量。
- 长文档首次只读相关章节，后续只读变化段。
- 大输出在执行端筛选、统计或落盘，只返回支持当前判断的关键证据。
- 文件、规则、环境和输入未变化时，复用仍可追溯的验证结果。
- 图片和批处理任务按批固定输入与验收，只返工失败项。

## 压缩与恢复锚点

长任务在压缩、跨窗口或阶段变化前更新一个增量锚点，至少保留：目标、验收、不做项、授权、决定、精确标识、活跃错误、最新验证、风险和下一动作。恢复时先读取锚点，再按需追溯证据，不重读全部资料。

## Memmy 或其他记忆系统

外部记忆应作为历史线索，而不是当前事实来源。推荐原则：

- 对指定工作空间关闭自动召回、自动采集和自动提交，但保留既有历史。
- 只有用户明确要求回忆，或完成当前任务确实缺少历史事实时才查询。
- 限制返回条数和正文总量，并携带来源以便核对。
- 过滤过期、重复、无关和敏感内容。
- 当前用户指令、项目状态与工作区文件始终优先于记忆。
- 记忆服务不可用时，当前任务仍应继续，不把它当成硬依赖。

公开仓库中不要提交真实 Hook、数据库、缓存、备份、本机路径、账号配置或服务地址。这个仓库也不提供任何第三方记忆工具的代码。

## 最小验证矩阵

改变上下文或记忆规则后，至少检查：

| 场景 | 预期行为 |
| --- | --- |
| 工作空间根目录 | 常驻规则生效，不自动注入历史记忆 |
| 项目子目录 | 继承工作空间规则，并读取项目自己的状态真源 |
| 同仓库 worktree | 行为与主工作区一致 |
| 名称相似但不属于该工作区的路径 | 不被错误排除或套用规则 |
| 用户明确要求回忆 | 仅返回少量相关片段并提供来源 |
| 记忆服务不可用 | 任务继续，说明缺少的历史证据 |
| 插件或应用更新后 | 重新确认 Hook 入口与作用范围 |
