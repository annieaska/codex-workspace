# 护肤科普研究台

从 `index.html` 进入共用研究台，或打开 `SK-BEH-001.html`（行为型）与 `SK-RES-001.html`（结果型）独立阅读；同名 JSON 与各自 HTML 的内嵌材料一致，可直接导入研究台。两次实际研究均为 **trial_with_gaps（含关键缺口的试运行）**，不是正式合格研究包。平台兴趣、科学证据质量及覆盖缺口按原始记录保留。

页面可原位阅读完整材料、审阅各分支、独立记录科学和兴趣门槛，并冻结审阅、方向与最终包。每次决定须明确实际身份和理由。程序核验结构、引用、哈希和门禁，不替代专业质量判断。主控原始决定、冻结时间和审计内容保留为只读历史；当前工作台修改或继续处理，需要新确认，不能冒用历史确认。

本页不自动搜索。Codex 按唯一 run-config.json 的预算取证，返回真实查询与消耗。工具返回量与实际筛读量分列；未知不填满额，预算算术通过不代表全部执行守约。含关键缺口时只能明确选择试运行，正式方向必须同时通过科学与兴趣门槛。

“保存到本机”依赖当前浏览器；导出 JSON 或 HTML 可跨浏览器保留。HTML 内含材料、策略审计副本、代码和冻结内容，没有在线字体或代码库。现代浏览器可直接打开；本轮以本地 HTTP 检验，工具限制导致 file: 双击路径未实测，存储受限时使用文件导出。

第三主题先选择模式并填写目标、核心问题、排除范围和产品角色。S0 通过仅表示任务可交给 Codex 取证，不表示研究完成；其他规则仍绑定唯一策略。

构建：`python3 build_workbench.py --data <行为研究JSON绝对路径> --data <结果研究JSON绝对路径> --split`。构建器从原研究同目录读取外部审计并校验哈希，向成果副本嵌入原始payload；不改原研究或审计文件。成果JSON可直接导入，原始外部审计JSON应先经构建器嵌入payload。`workbench-core.js` 是页面与定向检查共用逻辑。

`demo.html` / `static-fixtures.json` 是保留的阶段2演示，不是真实证据。项目临时目录内测试夹具同样不是实际研究。
