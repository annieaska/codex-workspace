## 1. 本次校准结论

阅读化妆品业务规则和“内容研究能力-产品盘点类”后，v0.1 的核心业务判断继续成立：

- 用户在输入主题时明确它是行为型还是结果型。
- 先建立分支地图，再进行专业审阅和优先级判断。
- 候选方向是上述判断完成后的下游产物，不能提前生成。
- 正式候选方向同时通过专业成立性和用户兴趣两道门槛。
- 行为型与结果型分别使用自己的优先级和见效层级。
- 所有真实材料、用户兴趣数据和同行内容都保留来源与原文入口。
- 新页面先做静态样例，再接入真实资料与能力。

但 v0.1 需要新增或校准以下内容：

1. 护肤科普类不再作为收件箱中的孤立能力，而是化妆品“内容研究能力”下与产品盘点类并列的正式模块。
2. 搜索、证据、来源、知识对照、人工确认、冻结版本等共用规则统一引用业务规则真源，不在本 BRD 中另造一套。
3. “知识库先约束再搜索”校准为“任务范围与术语先约束、外部最新资料先调查、再与本地知识比较”，避免已有知识压缩新发现空间。
4. 增加 S0–S3 搜索控制、分支覆盖矩阵、知识差异状态、证据身份与适用性判断。
5. 明确产品盘点的产品图谱、全量产品覆盖和重点深挖比例不是护肤科普的默认规则。
6. 明确研究包必须作为独立成果成立；后续写稿可以另行开展，但不依赖本项目的成果输出，本项目也不定义写稿交接契约。

## 2. 真源与版本边界

真源优先级固定为：

1. 用户当前明确指令。
2. `03_知识库/01_领域知识/化妆品业务规则/` 中最新已确认规则。
3. 本项目 `PROJECT.md` 中的项目决定和门禁。
4. v0.1 原始需求基线与本补充文件。
5. 历史静态页面、设计稿、聊天摘要和演示数据。

对象边界为：

- 化妆品业务规则目录：跨项目复用的业务定义、规则和质量门槛。
- 护肤证据知识库：来源、证据、主张、历史知识和研究包的业务数据真源。
- 本项目：护肤科普类的业务状态、分类逻辑、人工决定和交付物。
- 产品盘点项目：并列模块和复用参考，不是本科普类的需求真源。

每次研究运行必须绑定所用规则版本。规则更新不得静默重算已经冻结的研究结果；需要重算时生成新版本，并保留原因、差异和人工决定。

共用 S0–S3 协议、预算和停止规则以 `03_知识库/01_领域知识/化妆品业务规则/04_搜索分级与停止规则.md` 为准；分类配置、来源访问矩阵和任务覆盖治理以同目录 `09_共享搜索协议与配置继承.md` 为准。本文件只记录护肤科普分类的功能投影，不另建公共规则真源。

## 3. 与产品盘点类的关系

### 3.1 共用研究底座

两类能力共用：

| 共用能力 | 对护肤科普的含义 |
| --- | --- |
| 研究范围确认 | 搜索前明确主题、模式、人群、地区、平台、时间和排除范围 |
| 外部最新资料优先 | 先发现当前证据和用户讨论，再与本地历史知识比较 |
| 来源与主张可追溯 | 每条关键结论回到原始来源和精确定位 |
| 证据评估 | 区分来源身份、质量、独立性、适用性和复现状态 |
| 反向证据与缺口 | 不只收集支持材料，保留冲突、限制和未解问题 |
| 人工专业门禁 | 系统初判不能代替专业用户最终决定 |
| 自定义方向与增量补证 | 用户可自然语言提出方向，只对缺口追加研究 |
| 冻结与版本 | 新资料不能覆盖已确认结果，所有变化可追溯 |
| 知识分层 | 研究结果与资料按资格进入候选入库流程 |
| 独立研究交付 | 直接产物是自洽、完整、可审阅的研究包；后续如何使用不改变本项目职责 |

### 3.2 必须独立的分类逻辑

两类能力不得合并以下逻辑：

| 产品盘点类 | 护肤科普类 |
| --- | --- |
| 从品牌产品、配方技术与市场变化出发 | 从用户指定的行为或皮肤结果出发 |
| 主要寻找产品技术线与市场线的交叉 | 主要寻找分支机制、时间、风险和优先级的真实差异 |
| 候选角度可由产品更替、销量、舆情和技术证据交叉产生 | 候选方向只能在分支地图与专业审阅完成后产生 |
| 产品是主要研究对象 | 产品只是已确认解决方案的承接对象 |
| 需要产品身份、版本、配方与承接关系 | 需要行为／结果定义、原因分支、机制、时间、人群和处置关系 |

### 3.3 不默认继承的产品规则

以下规则只属于产品盘点，不自动进入护肤科普：

- 品牌全量产品身份 100% 覆盖。
- 去重产品总数 20%–35% 的重点深挖比例。
- 产品家族、法定产品记录、配方快照和产品承接图谱。
- 产品上新、替换、下架以及“换名＋换配方”的升级真实性触发规则。

只有本期护肤主题明确把某个品牌、产品线或具体产品作为研究对象时，才按实际范围引用相应产品规则；不得因此把整次护肤科普变成产品盘点。

## 4. 校准后的端到端业务流程

```text
用户输入主题并指定行为型／结果型
        ↓
S0 范围确认：目标、术语、边界、人群、地区、平台、时间和排除项
        ↓
优先调查外部最新资料
        ├─ 专业证据线：定义、现象、机制、时间、人群、风险、方案
        └─ 用户需求线：用户语言、相关问题、同行内容和初步需求信号
        ↓
与护肤证据知识库比较：新增、佐证、更新、冲突、缩小范围或缺口
        ↓
按行为型／结果型建立分支地图和分支覆盖矩阵
        ↓
形成系统初判、优先级建议、反向证据和缺口
        ↓
用户专业审阅、纠正、补充并选择可进入选题分析的分支
        ↓
从已确认的真实差异中生成候选方向草案
        ↓
为各草案建立本地化关键词簇并验证目标平台／地区的用户兴趣
        ↓
按“专业成立性 × 用户兴趣”形成正式候选方向
        ↓
用户选择、合并、排除或自定义本期方向
        ↓
只针对选定方向的证据缺口做增量补证
        ↓
冻结并交付独立研究包
```

广泛的用户问题和同行内容可以在第一轮扫描中收集，但不得在专业分支尚未成立时直接生成正式候选方向。

后续写稿属于独立能力，可以另行启动，也可以自行选择是否参考本研究包；它不是本流程的下游状态，不以本项目完成为启动条件。

## 5. 新增功能需求

### FR-SK-01 研究范围与 S0 门禁

搜索前必须确认：

- 研究主题与行为型／结果型模式。
- 内容目标和需要回答的核心问题。
- 目标人群、受众地区、平台和语言。
- 时间范围、临床／日常护理边界及明确排除项。
- 本期必须覆盖的来源类型和搜索预算。

范围不完整时处于 `S0`，禁止开始无边界搜索。未指定时，用户兴趣与同行内容观察默认使用 YouTube、Instagram，受众地区按东亚、北美、东南亚、欧洲依次降低权重。

上述平台和地区默认值只约束用户需求与内容市场观察，不限制科学证据的来源地区和语言；专业证据仍应根据问题在全球、多语言来源中寻找，并单独评估适用性。

### FR-SK-02 外部资料优先与本地知识比较

每次研究先调查外部最新资料，再调用护肤证据知识库做历史对照。知识库在搜索前可以提供术语归一、已知边界和错误表述提醒，但不能作为只允许搜索既有观点的过滤器。

新资料与本地知识的关系至少标记为：

- `new`：新增知识。
- `corroborates`：佐证已有知识。
- `updates`：更新已有知识。
- `contradicts`：与已有知识冲突。
- `narrows_scope`：缩小原有结论适用范围。
- `local_only`：仅在本地已有，外部本轮未找到对应资料。
- `gap`：需要但尚未获得。

新资料不得静默覆盖旧结论或人工判断。

### FR-SK-03 S1–S3 搜索控制

研究运行继承公共规则。以下数值是 `cosmetics-business-rules v1.3` 的当前配置投影，运行时仍须绑定实际 `ResearchPolicyProfile` 版本与内容哈希：

- `S1 全景扫描`：每类来源最多 3 种有效查询改写，每次最多保留 10 个命中，首轮合计最多深读 40 个合格来源。
- `S2 定向深挖`：仅在关键分支缺证、证据冲突、高风险分支、候选方向缺关键证据或知识差异需要解释时触发；每个目标最多追加 6 次改写和 30 个合格深读来源。
- `S3 人工放行`：登录、付费、验证码、用户凭据限定来源或超预算搜索必须由用户决定；robots、`429`、访问封锁或平台禁止自动化时必须停止该访问路线并登记缺口，不能借 S3 绕过。

只有同时满足以下条件才可停止：

1. 分支覆盖矩阵已经完成，或者每个未完成项均登记缺口及其影响。
2. 连续两次有效查询改写没有新增合格原始来源、原子主张或实质冲突。
3. 当前等级预算已经耗尽；若继续需要 S3，则停止并等待人工放行。
4. 候选方向的阻塞证据已经满足，或已确认在允许来源中无法取得。

搜索命中不是证据。没有进入原始来源并完成身份、定位和作用判断的内容不得进入结论。

### FR-SK-04 分支覆盖矩阵

每个进入主地图的分支至少需要记录：

- 分支定义及其在知识链中的位置。
- 上游原因、下游结果以及与其他分支的关系。
- 出现、持续、恢复或进展时间。
- 适用人群、场景、放大／减弱因素和排除边界。
- 支持来源、反向来源、证据身份、质量和适用性。
- 可以支持与不能支持的表达。
- 系统初判、用户专业决定和未解决缺口。

只有相关分支完成上述覆盖，或缺口已由用户明确接受，才能生成正式候选方向。

### FR-SK-05 来源与证据资格

每条关键资料至少保留：

- 原始标题、URL 或稳定标识。
- 作者、机构、发布者或平台。
- 发布／更新状态日期和采集日期。
- 适用人群、市场、语言、时间和产品版本（如涉及具体产品）。
- 页码、段落、表格、图号、权利要求或视频时码等精确定位。
- 与本期分支或主张的具体关系。

必须区分：独立研究、品牌／原料方研究、专利、监管资料、品牌宣传、媒体、用户叙述、同行内容、系统推断和人工专业判断。资料分别评估来源身份、方法质量、独立性、适用性和复现状态。

论文 `≥80／60–79／<60` 分层与专利产品相关度 `≥70` 是公共规则已确认的版本化可配置默认值，不是永久常量。本项目不得硬编码；每次运行记录实际阈值、规则版本与任务覆盖状态，且致命方法缺陷优先于分数和阈值映射。

### FR-SK-06 两种模式的专业优先级

行为型继续使用“改善收益优先级”，至少比较：

- 结果与该行为的关联度和视觉识别权重。
- 出现时间、持续时间、可逆性和复发可能。
- 风险、影响大小、主观体感与改善幅度。
- 见效速度、可执行性、成本和证据强度。

结果型继续使用“原因处置优先级”，按以下逻辑审阅：

1. 紧急安全风险与延误后果。
2. 因果链中的上游程度。
3. 后果严重性、持续性和不可逆风险。
4. 是否诱发、维持或放大其他表现。
5. 发生可能性和可区分线索。
6. 对应处置的体感、速度和改善幅度。

两种模式均可显示时间信息，但不得共用一套“最快见效即最高优先级”的排序。

### FR-SK-07 候选方向双重准入

候选方向只能从审阅后的真实差异中生成。每个方向必须同时展示：

- 来源分支、专业判断和关键材料标题。
- 能支持、不能支持和仍缺少的内容。
- 关键词簇、地区／平台表达、热度或需求信号及数据局限。
- 同行供给、用户问题与可解释的内容空缺。
- 适用人群、表达边界和风险。

用户兴趣是内容市场信号，不是科学证据。高热度不能挽救伪命题或证据不足；低热度也不能直接否定专业价值，应先检查是否需要把学术语言转换为用户语言。

系统不得用未确认的黑箱总分自动选择方向。用户可以自然语言合并、排除、补查或自定义方向；自定义方向默认只做增量补证。

### FR-SK-08 同行内容来源完整性

每条同行内容至少显示平台、作者／账号、原始标题、发布日期、内容形式、互动指标及快照日期、原内容链接、纳入原因、关联分支／方向、可启发内容和不能证明的内容。

同行内容不参与科学证据权重，只用于观察用户语言、关注问题、表达方式和内容供给缺口。

### FR-SK-09 解决方案与产品承接

解决方案必须从已经确认的机制、原因、风险和适用边界产生。产品只能承接解决方案中的具体角色，不得反向决定结论。

涉及具体产品时，至少说明：

- 产品解决哪一层问题，对应哪条机制或方案。
- 适用与不适用的人群、场景及风险提醒。
- 产品、配方、市场和时间版本。
- 哪部分是品牌主张，哪部分有独立证据支持。
- 证据是针对原料、配方还是完整上市产品。

若本期仅讨论解决路径而不需要具体产品，可以不强行加入产品；研究包应记录“本期无产品承接”及其理由。

### FR-SK-10 冻结、审计与知识入库候选

第一阶段审阅结果、第二阶段方向决定和最终研究包分别冻结，至少保存：

- 原始输入、范围、默认值和所用业务规则版本。
- 搜索等级、预算、查询、深读、停止理由和访问缺口。
- 资料、分支、主张、系统初判和人工决定之间的关系。
- 被排除内容、反向证据、接受的风险与尚未解决的缺口。

本项目不直接读取知识库底层数据库，也不在缺少正式写入契约时自动入库。研究结束后只生成版本化的知识入库候选；去重、覆盖、撤销和最终入库由知识库契约与人工门禁处理。

### FR-SK-11 独立研究包与项目边界

本模块的直接交付物是**冻结研究包**。研究包必须作为独立成果完整成立，不以适配某个写稿能力为验收条件，至少包含完整知识链、分支结论、优先级、解决方案、产品角色、证据、反证、边界、缺口和原文入口。

本项目不额外生成强制性的“写稿交接信息”，也不规定后续写稿必须读取本研究包。后续写稿是可另行开展的独立能力，可以根据自己的任务输入选择参考本研究包、用户专业知识、知识库或其他资料。

两者之间不得建立以下耦合：

- 不把写稿建模为本项目的下游状态。
- 不把本项目完成设为写稿启动条件。
- 不要求写稿必须消费本项目的字段、版本或交付物。
- 不因写稿流程变化而反向修改本项目的研究包结构。

如果未来的写稿工作发现新的研究问题，可以提交一项新的研究请求；该请求属于新的任务输入，不是固定的回退状态或运行依赖。本项目不实现自动写稿。

| 第 14–15 节“候选方向与热度” | 保留双重准入；明确热度只决定内容需求，不改变科学真实性 |
| 第 16 节“同行内容” | 保留，并明确它只属于用户需求线 |
| 第 17 节“最终研究包” | 增加研究包的独立完整性、冻结和非依赖边界，不建立写稿输入契约 |
| 第 18 节“冻结对象” | 新增规则版本、搜索预算、停止理由和知识差异快照 |
| 第 19–20 节“页面与静态样例” | 继续坚持静态样例先行；只复用通用组件与交互，不自动继承产品盘点类的页面主线与已选视觉方向 |

## 7. 已确认、待确认与不适用

### 7.1 已确认并继续有效

- 行为型／结果型双模式。
- 分支地图、专业审阅和优先级选择先于候选方向。
- 专业成立性与用户兴趣双重准入。
- 默认平台及受众地区优先级。
- 原始链接、来源信息和同行内容身份完整。
- 静态样例先行。
- 跨项目业务规则是真源，本项目不重复维护同一规则。
- 后期写稿与本项目解耦，可以作为独立后续工作开展，但不依赖本项目的成果输出。

### 7.2 本次新增，已人工确认

- 护肤科普真实研究采用 S0–S3 共用预算和停止规则。
- 分支覆盖矩阵作为生成正式候选方向的硬门槛。
- 科学证据搜索不受默认目标地区权重限制；地区权重主要服务用户兴趣和同行内容观察。
- 单次任务只可直接覆盖主题／模式、对象／人群／市场、平台／语言／时间窗、研究重点、来源侧重及更严格预算；扩大预算、接受关键缺口、调整证据阈值或使用登录／付费来源必须人工确认，公共硬门禁不可覆盖。

### 7.3 不适用或有条件适用

- 产品全景覆盖、重点深挖比例和产品更替规则默认不适用。
- 具体产品、配方和市场版本规则仅在研究包出现具体产品主张时适用。
- 产品盘点项目已确认的信息架构与视觉方向不自动成为本科普类定稿。

## 8. 对下一版静态样例的需求影响

需求确认后，下一版静态样例需要优先验证：

1. 第一屏能够确认主题模式、范围、默认平台／地区和本次规则版本。
2. 研究资料、知识差异、分支覆盖与专业审阅形成一条可理解的主线。
3. 行为型／结果型切换时，分支结构、优先级和见效层级真实变化。
4. 候选方向仍在审阅后出现，并能就地查看关键材料标题、链接、热度证据和表达边界。
5. 页面能显示搜索覆盖、缺口和停止理由，但不把研究预算做成用户的主要认知负担。
6. 最终研究包页展示内容完整性与冻结版本信息，不增加“交给写稿”的流程或强制交接字段。
7. 继续使用演示数据，并修复任何无法滚动到底、固定操作遮挡内容或要求用户跨菜单拼接逻辑的问题。

本阶段仍不铺真实材料。静态结构经人工确认后，才进入真实研究、知识库接入或系统实现。
