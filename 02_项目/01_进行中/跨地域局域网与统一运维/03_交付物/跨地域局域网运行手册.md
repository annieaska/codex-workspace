## 稍后使用时的最小只读检查

1. 固定发起端、目标站点、目标 IP 和真实业务端口。
2. 在瑞典侧查看目标 `/24` 的真实下一跳和出接口，确认归 `wg-data`。
3. 核对瑞典、荷兰、阿里云和目标站点相关 peer 的最新握手与双向计数。
4. 在中继和目标网关分别执行 `ip route get <目标IP>`；涉及回程时绑定真实 LAN 源地址检查反向路径。
5. 先探测站点网关，再探测代表终端的真实端口；用前后接口计数确认流量确实走预期数据面。
6. 如要求长期可用，再做对应配置真源、接口 reload 或重启后的持久性验证。

常用只读命令模板：

```bash
ip -4 address show
ip -4 route show
ip -4 rule show
ip route get TARGET_IP
wg show wg-data allowed-ips
wg show wg-data latest-handshakes
wg show wg-data transfer
```

OpenWrt 还需核对：

```sh
uci show network | sed -E "s/(private_key|preshared_key)=.*/\1='[REDACTED]'/" | grep -E 'wgdata|wg-data|allowed_ips|route'
uci show firewall | grep -E 'wgdata|wg-data'
```

## 验收口径

- 节点 SSH 成功：只证明管理入口可用。
- peer 有握手：只证明隧道最近有通信。
- 网关 ping 成功：只证明该方向到网关可达。
- 代表终端真实端口成功且回程正确：证明该项业务端到端可用。
- reload/重启后仍通过：才证明相应持久化配置可用。

任何一步都不能替代下一步。尤其不能用“荷兰能 ping 国内网关”替代“瑞典普通 LAN 客户端能访问国内代表终端”。

## 施工边界

- 不设置 `0.0.0.0/0`，不接管普通上网默认路由。
- 不把站点 LAN `/24` 重新放回 `wg-term`。
- 不修改 `wg-game`。
- 一次只处理一个站点；先并行建好新路径并完成双向、业务、持久性验证，再撤旧路径。
- 写入前确认实际加载的 systemd/UCI 配置真源，并保留至少一个不依赖待改接口的管理入口。
- 旧工作区的施工授权均已消费，稍后任何远端写入都需要新的明确授权。

## `lovewhowho.net` 公网证书下发边界

工作区自动化真源位于 `03_交付物/scripts/证书自动续期/`，其中 `README.md` 记录工作区文件到 VPS 运行路径的映射、下发链路、变更顺序和验收标准；VPS 上的脚本与监控配置只是运行副本。证书正文仍由荷兰 VPS 的 `/root/.acme.sh/lovewhowho.net_ecc/` 生成，私钥和 DNS API 凭据不得写入工作区。

2026-09-22 已核对并修复通配符证书自动续期链路。`acme.sh` 续签钩子调用 `/usr/local/bin/deploy-lovewhowho-wildcard-cert.sh`。下发脚本直接扫描 OpenResty 当前生效的 `conf.d`，按实际 `ssl_certificate` / `ssl_certificate_key` 路径部署，不再依赖 1Panel 网站数据库，因此手工配置的 `ops`、`auth`、`study`、`fnos-se`、`synology` 及容器命名空间软链也在覆盖范围内。

- 每次下发前校验证书 SAN、有效期和证书/私钥匹配关系，并执行 OpenResty 配置检查。
- 每次下发会在 `/var/backups/lovewhowho-cert/` 保存目标文件备份；写入、配置检查、平滑重载或逐域指纹验证失败时自动恢复。
- ACME 和兜底巡检每天 `06:40/18:40`、`06:50/18:50` 各执行一次，日志分别为 `/var/log/lovewhowho-acme.log` 和 `/var/log/lovewhowho-cert-check.log`，由 `/etc/logrotate.d/lovewhowho-cert` 轮转。
- `/opt/ops-monitor` 每分钟执行快速证书探针；源证书不足 21 天、任一部署文件漂移或关键域名仍提供旧证书时，沿用现有运维告警通道。
- 人工只读核验：`/usr/local/bin/check-lovewhowho-wildcard-cert.sh --check-only`。需要重新下发时：`/usr/local/bin/deploy-lovewhowho-wildcard-cert.sh --deploy`。

当前资产清单中的 7 台 OpenWrt（瑞典 `192.168.50.2`、北京 `192.168.110.7`、北花园 `192.168.130.2`、赵杰 `192.168.7.4`、于宏志 `192.168.18.3/18.4/18.7`）均使用 `/etc/uhttpd.crt` 和 `/etc/uhttpd.key` 的设备自签名证书，通过 IP 管理；配置中没有 `lovewhowho.net` 域名或公网证书下发地址。不得把同一张公网通配符私钥复制到这些边缘设备：通过 IP 访问仍会发生名称不匹配，同时会扩大私钥暴露面。如以后需要可信的路由器 HTTPS，应先分配独立主机名，再按设备签发独立证书或采用内部 CA。

NAS 等公开域名当前由荷兰 VPS 的 OpenResty 终止 TLS，后端终端不需要接收公网通配符证书；只有未来改成终端直接终止公网 TLS 时，才新增独立下发目标并登记在本节。
