# 跨地域局域网与统一运维

## 问题

瑞典家经荷兰 VPS 访问北京公司、北花园、赵杰等站点 LAN 的资料，过去分散在旧项目、系统网络方案和连接资产中；原“`Nebula跨机组网`”名称只体现管理入口，容易把 Nebula 节点可达误认为整个站点 LAN 已可达。

## 目标

建立当前工作区的唯一入口，统一记录跨地域 LAN 的拓扑、站点网段、管理平面、数据平面、验证状态与安全操作边界，供后续连接、诊断和施工直接使用。

## 范围

- 瑞典家 `192.168.50.0/24`。
- 北京公司 `192.168.110.0/24`。
- 和平里 `192.168.120.0/24`。
- 北花园 `192.168.130.0/24`。
- 赵杰 `192.168.7.0/24`。
- 于宏志站点 LAN `192.168.18.0/24`：18.3 是虚拟机 `8894` 及 Nebula88 `192.168.88.94` 的当前 LAN 身份；18.4 是数据面网关及 Nebula66 管理入口；18.7 是历史节点及其 `192.168.66.35` 管理入口。
- 荷兰 VPS、阿里云 VPS、Nebula 66/88/19266、`wg-term`、`wg-data` 及荷兰—北京直连运输面。

## 非目标

- 不保存或迁移私钥、密码、token、证书正文和 `.env` 内容。
- 不接管普通上网默认路由，不把站点 LAN `/24` 放入 `wg-term`。
- 不把历史记录、单向 ping、节点 SSH 或一次握手扩大表述为全站点端到端可用。

## 公网证书下发真源

- 证书自动化的工作区真源是 `03_交付物/scripts/证书自动续期/`；下发流程、文件映射、变更顺序、设备边界与验收标准见该目录的 `README.md`。荷兰 VPS 上的脚本和监控配置是部署后的运行副本，不作为长期编辑真源。
- `03_交付物/跨地域局域网运行手册.md` 的“`lovewhowho.net` 公网证书下发边界”是日常运行说明真源。证书正文由 VPS 的 ACME 目录生成，证书正文、私钥和 DNS API 凭据不进入工作区。
- 2026-09-22 已关闭本轮证书漏下发问题：统一脚本按 OpenResty 当前生效配置动态发现实际路径，完成 `26` 个目标文件和 `30` 个 TLS 域名下发；外部证书链、主机名和指纹验证 `30/30` 通过，线上证书到期时间为 `2026-12-21 03:42:10 UTC`。
- 资产清单中的 7 台 OpenWrt 不接收公网通配符证书：它们当前通过 IP 使用设备自签名证书；复制通配符私钥既不能解决 IP 名称不匹配，也会扩大密钥暴露面。NAS 等公开域名由 VPS 的 OpenResty 终止 TLS，后端同样无需接收证书。
- 不能算通过：只看到 ACME 续签成功、只验证 `panel`、只复制文件，或只看到 OpenResty 重载成功。关闭证据必须同时覆盖工作区与远端六个常驻文件一致、OpenResty 配置检查、动态发现的全部线上 SNI，以及证书链和主机名验证。
