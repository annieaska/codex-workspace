# Game V2 独立安装器

状态：cy507 第 1 项 W7/FakeTCP、第 2 项 Xbox NAT 与第 3 项 DNS 均已完成技术和 Xbox 业务验收并正式提交；本轮四项问题关闭，范围始终仅限 cy507

## 问题与目标

为个人自用和朋友使用提供一套可审查、可离线验证的 Game V2 双端安装器。服务端是一台 Debian VPS，客户端是若干 OpenWrt 路由器；安装器负责基础依赖、独立隧道与加速进程、路由/防火墙、客户端安装包、验证及安全卸载。

## 已确认范围

- 项目等级：个人自用的轻量部署；只保留安装、切换、恢复和真实连通所必需的能力，不引入企业级平台、复杂编排或冗余流程。
- VPS：仅 Debian、systemd、x86_64。
- 路由器：仅 OpenWrt 25.12、apk、x86_64。
- 一台 VPS 可登记多个 OpenWrt 客户端；每个客户端有独立 WireGuard 接口、密钥、地址、端口，以及独立 speederv2 密钥和端口。
- 一台 OpenWrt 可导入多个 VPS profile，但任意时刻最多激活一个；导入完成后保持 `inactive`。
- VPS 当前唯一安装入口：`game-v2-cy507-vps.sh preflight/apply/verify/commit/restore`。
- OpenWrt 当前唯一安装入口：`bundles/cy507-openwrt/install.sh preflight/apply/verify/commit/restore`。
- OpenWrt 安装同时部署路由器本地控制页 `/wgpanel.html`；页面只调用本机 CGI，提供节点状态、列表和单活切换。
- 安装入口仍分别在两端本机执行；运行时仅允许 OpenWrt 为当前 profile 通过专用身份、固定主机指纹和 VPS forced command 执行 FEC 六档配对事务，不提供通用跨机器编排。

## 非目标

- 不建设中央后台、数据库、多租户平台、监控中心或批量部署设施；路由器本地控制页不属于中央后台。
- 不保留旧的一对一安装流程、远程双端门禁或兼容层。
- 不支持其他 Linux 发行版、init 系统、OpenWrt 包管理器或 CPU 架构。
- 不把真实密钥、公网地址、凭据或现场日志提交到业务仓库。
- 不把旧 OpenClaw 系统或其运行依赖打进独立安装器。

## 关键决策与证据

- VPS 采用“一个共享基础层 + N 个客户端对象”。共享层只管理 VPS 级软件、转发和防火墙服务；删除单个客户端不会卸载共享依赖。
- 每个服务端客户端对象均有独立注册表、密钥目录、WireGuard 配置、systemd 单元、speederv2 环境/启动器和对象清单。
- 注册表修改使用锁；新增时检查全部已登记客户端，而不是只检查当前监听端口。检查同类端口/地址/路由冲突，也检查 VPS 上 WireGuard 与 speederv2 的跨角色 UDP 端口冲突及 WG 地址交叉冲突。
- OpenWrt 采用“一个共享基础层 + N 个候选 profile + 0..1 个 active profile”。`join` 只登记候选项，不改共享 fw4 区域、不启动链路。
- OpenWrt 激活由本地事务控制：先验证目标，停止旧 profile，切换 UCI/fw4，再启动目标；失败时清除 active 与转发并保持 fail closed，不恢复旧线路。中央 `game-v2-restore` 是唯一开机入口；各 profile 服务保持 disabled，只由控制器显式启停。恢复与验证必须核对服务、接口、精确 source rule、策略表默认路由和两条服务端路由。
- OpenWrt 防火墙只通过 UCI/fw4 管理并 reload；不创建自定义底层 hook/base chain，也不设置全局 drop 策略。
- OpenWrt Game zone 对整个 `route_cidr` 做 masquerade，将 LAN 流量统一转换为 profile 唯一客户端 WG `/32`；VPS peer 与出口 NAT 只按该 `/32` 和游戏接口识别客户端，使不同家庭可复用相同 LAN 网段且不污染其他线路。
- VPS 只自愈安装器拥有的 `game_v2`/`game_v2_nat` 表和 `ip_forward`，不自动删除其他组件的防火墙对象；完整规则集合按 registry 确定性重建，定时 reconcile 与 registry 写操作共用同一把锁。
- 路由器本地页面作为 OpenWrt 安装资产部署；它通过本机 `wg_api.sh`、`wg_nodes.sh` 和 `web-panel.sh` 适配现有 profile/单活控制，不引入远端控制面。旧项目已验证的 FEC 六档参数与双端执行属于必须保留的产品能力，不得以“轻量收敛”为由删除。
- FEC 配对控制采用每 profile 专用 SSH 密钥、固定 `known_hosts` 和 VPS `restrict` forced command；仅接受状态、验证和六档精确 apply 命令，不接受任意参数，也不形成兼容层或通用远程 shell。
- 私钥和 speederv2 密钥只写入 `0600` 文件；临时文件先设为 `0600` 再写。OpenWrt 私钥通过 UCI batch 标准输入传递，不进入进程参数；日志和非秘密注册表不含秘密值。
- 删除前按对象清单核验允许路径与所有权 marker；不匹配即拒绝。存在客户端/profile 时禁止卸载共享基础层。
- 旧远程一对一入口已退役，不作为新流程的一部分，也不提供兼容转发。
